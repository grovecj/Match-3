# Art sources

Source files (e.g. `.blend`) that are *not* imported directly by Unity live here.
Unity ignores everything outside `Assets/`. Export finished sprites/models into `Assets/`.

Binary formats are tracked with Git LFS (see `.gitattributes`).

## Achievement icons (`Icons/`)

`Icons/build_achievement_icons.py` draws the achievement icons into
`Assets/Sprites/Achievements/` with Pillow: white shapes on transparent, which the UI tints.
The file name is the icon name the server uses. See `Docs/Achievements.md`.

```
python Art/Icons/build_achievement_icons.py
```

`Icons/build_ui_icons.py` draws the other small UI icons the same way, into
`Assets/Sprites/UI/`. So far that's `Play.png`, the triangle on each sound set's preview
button in Settings.

```
python Art/Icons/build_ui_icons.py
```

## Token sprites (`Gems/`)

The six tokens are generated by a Python script rather than modeled or drawn by hand, so
they can be rebuilt and tweaked reproducibly. The script renders them in three **styles**,
each one a `TokenStyle` asset in `Assets/Data/TokenStyles/` that the player picks in Settings:

| Style   | Look                                    | Sprites                                     |
|---------|-----------------------------------------|---------------------------------------------|
| `gems`  | faceted, glossy, opaque cut gems        | `Assets/Sprites/Gems/Gem<Name>.png`         |
| `glass` | smooth rounded tiles of backlit glass   | `Assets/Sprites/Glass/Glass<Name>.png`      |
| `flat`  | solid 2D shapes with a dark border      | `Assets/Sprites/Flat/Flat<Name>.png`        |

- `Gems/build_gems.py` builds each style's meshes, materials, lights and camera, saves
  `Gems/<style>.blend`, and renders each token to a 256x256 PNG with a transparent background.
- The `.blend` files are the generated scenes: open one in Blender to look around or
  experiment. They're overwritten each time the script runs, so make lasting changes in the
  script.
- All styles share the same six outlines, so tokens are told apart by **shape alone**
  (colorblind-friendly). Keep it that way when adding a style.

To rebuild (from the repo root; Blender is in the Steam install on this machine):

```
blender --background --python Art/Gems/build_gems.py                  # every style
blender --background --python Art/Gems/build_gems.py -- --style glass  # one style
```

Unity picks up the new PNGs automatically. Their import settings (Sprite, Single, 256 Pixels
Per Unit so one token fills one board cell) live in the `.png.meta` files and are kept across
re-renders.

### Adding a token type

1. Add a row to `SHAPES` in `build_gems.py` (an outline no other token has, and a colour) and
   render every style. If the existing PNGs come out changed only by render noise, put them
   back with `git checkout` so the commit holds just the new ones.
2. Give each new PNG the same import settings as the others (the simplest way outside Unity
   is to copy a neighbour's `.png.meta` and give it a new `guid` and `spriteID`).
3. **Create > Match3 > Token Type** in `Assets/Data/TokenTypes/`, with a unique id.
4. Add an entry for it (sprite and burst colour) to every `TokenStyle` asset, and add the type
   to the Board's **Token Types** list in the Game scene. `TokenStyleAssetTests` checks both.
5. Check the Settings preview row still fits: `SettingsMenuBuilder` sizes its icons for the
   number of types.

A type added this way changes how often matches happen, so it's a gameplay change, not a
cosmetic one: see "Six token types" in `Docs/Scoring.md`.

### Adding a style

1. Add a `Style` to `STYLES` in `build_gems.py` and render it.
2. In Unity, select the new PNGs and set **Sprite Mode: Single** and **Pixels Per Unit: 256**
   (Unity's defaults are Multiple / 100).
3. **Create > Match3 > Token Style**, give it a unique id, and add one entry per token type.
4. Add it to the `ThemeManager`'s **Token Styles** list in the Game scene. The Settings menu
   shows it automatically, and `TokenStyleAssetTests` checks that it covers every token type.

## Sounds (`Audio/`)

Each folder is one **sound set**, a `SoundSet` asset in `Assets/Data/SoundSets/` that maps
every gameplay sound (Match3, Swap, ...) to a clip. The player picks one in Settings, and it
changes every sound at once. `Audio/<Set>/` keeps the source files: downloads exactly as they
came (plus the pack's license), or the presets a set is generated from. The clips Unity
imports live in `Assets/Audio/<Set>/`. Every file is listed with its source, author and
license in `CREDITS.md` at the repo root.

| Set      | Sound                                | Source                                        |
|----------|--------------------------------------|-----------------------------------------------|
| `chimes` | soft, glassy UI chimes and clicks    | Kenney's Interface Sounds (CC0)               |
| `arcade` | 8-bit blips, buzzes and power-ups    | made here with jsfxr (CC0)                    |

The one exception is the round-end horn, `Assets/Audio/Chimes/horn.wav`. The pack has no horn,
so `Audio/build_horn.py` synthesizes one (two notes a minor third apart, each a stack of
harmonics) using only Python's standard library. To rebuild it after changing the script:

```
python Art/Audio/build_horn.py    # writes Assets/Audio/Chimes/horn.wav
```

### The Arcade set

Arcade isn't downloaded at all. Every clip is generated by [jsfxr](https://sfxr.me), a
generator for the kind of sound effects 8-bit consoles made. A sound is described by a
**preset**: a couple of dozen numbers such as the waveform (square, sawtooth, sine or noise),
how long it holds and fades, its starting pitch, and how the pitch slides or jumps. The same
numbers always give the same sound, so `Audio/Arcade/<sound>.json` (one preset per sound) is
the source, and `Audio/build_arcade.js` renders each preset to `Assets/Audio/Arcade/<sound>.wav`.
It needs [Node.js](https://nodejs.org):

```
cd Art/Audio
npm install            # once: downloads jsfxr into node_modules/ (not committed)
node build_arcade.js
```

To change a sound by ear, open <https://sfxr.me>, paste the preset's JSON into the box under
**Serialize / Deserialize**, move the sliders until it sounds right, then copy the JSON back
into the file and run the script. A few of the numbers, to make the files readable:

| Preset field | Meaning |
|--------------|---------|
| `wave_type` | 0 square (the classic "beep"), 1 sawtooth (buzzier), 2 sine (pure), 3 noise (hiss) |
| `p_env_sustain`, `p_env_decay` | how long the sound holds at full volume, then how long it fades |
| `p_base_freq` | the starting pitch |
| `p_freq_ramp` | pitch slide: above 0 rises, below 0 falls |
| `p_arp_mod`, `p_arp_speed` | one sudden jump in pitch, and how soon it happens (the two-note "coin" sound) |
| `p_repeat_speed` | restarts the sound over and over, which turns a rising slide into a "power-up" |
| `p_duty` | how thin a square wave is; thinner sounds more nasal |
| `sound_vol` | the clip's loudness. Lower it if the script reports clipped samples |

Arcade's clips are imported with **Normalize off** (the other settings match the list below).
Normalize would stretch every clip to full loudness, and a square wave at full loudness is far
louder to the ear than a chime, so the presets' `sound_vol` sets the level instead.

### Import settings

Short sound effects all use the same import settings (select the clips in Unity to see them
in the Inspector):

- **Force To Mono: on.** The game is 2D and every sound plays from the middle, so a stereo
  file only doubles the memory for no audible gain.
- **Load Type: Decompress On Load.** The clip is unpacked to raw samples once, when the scene
  loads, so playing it costs nothing. Right for short, frequent sounds. (Long music would use
  *Streaming* instead, which decodes a little at a time from disk.)
- **Compression Format: ADPCM.** A light compression that is very cheap to decode and fine
  for short effects. Vorbis is smaller but heavier to decode and can blur very short clicks.
- **Preload Audio Data: on,** so the first play of each sound isn't delayed by loading it.

### Adding a set

1. Put the original files in `Art/Audio/<Set>/` and copies in `Assets/Audio/<Set>/`, and
   apply the import settings above to the copies.
2. **Create > Match3 > Sound Set**, give it a unique id and a display name, and drag clips
   into the slots. An empty slot just plays nothing while you're building the set, but
   `SoundSetAssetTests` fails until every slot is filled.
3. Add it to the `AudioManager`'s **Sound Sets** list in the Game scene. The Settings menu
   shows it automatically. (Three fit on a row; a fourth would start a second row and make
   the Settings window too tall for a 1080-pixel-high screen.)
4. Add every file to `CREDITS.md`.

## Particle textures (`Effects/`)

The clear explosion's particles use two tiny textures, generated by a Python script (needs
Pillow) rather than drawn by hand:

| Texture     | Used for                                  |
|-------------|-------------------------------------------|
| `Spark.png` | the colored shards of every burst         |
| `Glow.png`  | the white flash behind a 5+ burst         |

Both are pure white, with the shape in the alpha channel, so the ParticleSystem can tint each
particle to the token's burst color. To rebuild them, then the prefab that uses them:

```
python Art/Effects/build_particles.py    # writes Assets/Sprites/Effects/*.png
```

Then in Unity, with the Game scene open, run **Match3 > Build Explosion Prefab** and save the
scene. That tool sets the textures' import settings, makes their materials in
`Assets/Materials/`, builds `Assets/Prefabs/Explosion.prefab` and assigns it to the Board.
